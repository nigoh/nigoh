## 目的と「格」の定義（Hero showpiece との差別化）

| 軸 | Hero `ProunCanvas`（showpiece・主役） | 本書 `SectionAccent`（脇役・サブ） |
|----|--------------------------------------|-----------------------------------|
| 役割 | サイトの「掴み」。画面中央右を占める作品 | セクションの隅で気付く程度の点景。本文を絶対に邪魔しない |
| オブジェ数 | 6〜7 個 | **1〜3 個**（セクション毎） |
| 占有 | 画面の広い面積（`inset-0` 全面 canvas） | **1 隅の小さな矩形ビューポート**（おおむね画面短辺の 22〜34%） |
| 不透明度 | 0.82〜0.95 | **0.18〜0.40**（後退・点景） |
| モバイル | デスクトップ限定（`hidden md:block`） | **モバイルでも出す**（更に控えめに。要望に応える） |
| モーション | 緩慢な多軸ドリフト＋bob | **更に緩慢**（spin 上限を下げる）。bob は最小か無し |

> 一言で言えば: Hero は「読ませる作品」、本書は「セクションの角に置いた小さな浮遊彫刻」。
> **語彙は Hero と同じ Proun 語彙（box/楔/円環/棒/薄板）**を使い、密度・配色・配置で脇役化する。

## 1. 配置思想（本文非干渉・2D タイルと喧嘩しない＝「うるさくない」の担保）

### 1-1. 既存レイヤーとの z 構造（厳守）

各セクションは `<section class="relative ... overflow-hidden">` で、内部は次の重なり:

```
z-10  本文（max-w-6xl のコンテンツカラム）            ← 最優先・主役
z-0   ConstructivistCanvas（2D タイル・absolute inset-0） ← 既存の地の装飾
z-0   SectionAccent（本書・3D・absolute・1隅の小矩形）   ← 新規。2D タイルの「上」だが本文の「下」
```

- SectionAccent のホスト div は `absolute`・**1 隅に小さく**配置（`inset-0` の全面に広げない）。
  `aria-hidden="true"` / `pointer-events:none` / 本文（`z-10`）より下層（`z-0` 相当、本文に被らせない）。
- 2D タイル（`ConstructivistCanvas`、`inset-0` 全面）の**手前**に小さく重ねてよいが、**本文カラムの背後には置かない**。
  → 3D の小ビューポートは**セクションの外周の隅・余白側**に固定し、本文 `max-w-6xl` の読み幅と重ねない。

### 1-2. 「うるさくない」を担保する 3 つの具体策

1. **占有を限定する**: 3D は `inset-0` で全面展開しない。**1 隅 22〜34vmin 四方の小矩形**だけに描く。
   セクションの大半は従来どおり 2D タイル＋余白のまま。3D は「角の点景」に徹する。
2. **2D タイルと面で競合させない**: 3D を置く隅は、その隅の**2D タイル密度が元々疎な側**（本文回避で疎にしている余白側）に重ねる。
   2D が密な領域に 3D を重ねない（装飾の二重化＝うるささの原因を避ける）。隅の選定は下記セクション表で固定。
3. **不透明度で確実に後退**: ホスト全体 `opacity 0.18〜0.40`（セクション毎）。
   3D 単体で主張させず、2D タイルの上に**薄い浮遊点景**として乗る。明背景では black/red の輪郭で、暗背景では cream 稜線で「気付く程度」に。

### 1-3. 配置の基本ルール（全セクション共通）

- **本文カラム回避**: `max-w-6xl mx-auto` の読み幅（中央〜やや左の本文ブロック）の背後に 3D を置かない。
  3D は左右どちらかの**外側の縦帯**または**上下の隅**に寄せる。各セクションの本文の重心の**逆側**を選ぶ（下表で固定）。
- **見出し（H2）回避**: 各セクション左上の極大 H2（`text-5xl sm:text-6xl`）の直背後に 3D を置かない。
  H2 と同じ隅に置く場合は H2 の**外側**（さらに端）へ逃がす。
- **隣接セクションとの分離**: 連続するセクションで 3D を**同じ隅に連続させない**（上下に並ぶと縦の列に見え「うるさい」）。
  下表は左右・上下の隅を交互に振って、スクロール時にジグザグの点景リズムになるよう配置した。

## 2. セクション別 3D オブジェクト構成

### 2-0. 明背景 / 暗背景でのエッジ・配色の方針（厳守）

Hero showpiece と同じ原理を脇役向けに簡略化:

- **暗背景セクション（skills / career / contact、`bg-constructivist-black`）**:
  - 黒面（black `#1A1A1A`）は背景に沈むので、**cream 稜線（`EdgesGeometry` の `LineSegments`）で輪郭を見せる**。
  - cream 面は明るすぎて本文 cream 見出しと競合しうるので**面では使わず、稜線・細棒の輝点に限定**。
  - 主役色は **red `#D62828`**（black 上 ≒ 3.48:1、装飾として可）。red の小片＋cream 稜線の黒片で構成。
- **明背景セクション（about / ai / portfolio、cream `#F5F0EB` 地）**:
  - cream 面は背景に飛ぶので**面では使わない**。**black/red を主体**にする。
  - black `#1A1A1A` on cream ≒ 15.4:1、red `#D62828` on cream ≒ 4.42:1 — どちらも輪郭がはっきり出る。
  - 稜線は不要（black/red の実面で十分読める）。必要なら black 細稜線で定義を足す。
- darkgray `#3D3A37` は独立オブジェには使わない（陰面用だが本書は `MeshBasicMaterial` 想定で陰面なし）。
  使うなら明背景での「黒の弱い対」として box 面に 1 個まで（red/black の主役を食わない範囲）。

### 2-1. オブジェクト表（frontend 実装の直接の入力）

> 寸法比は「世界単位」（各セクションの小シーンの frustum 基準。後述 §5 で frustum を決める）。
> 配置隅 (x,y) は**ホスト矩形を置くセクション内の隅**（CSS。例: `bottom-right`）。傾きはラジアン相当を度で表記。
> spin は rad/秒（脇役なので Hero より遅い **0.01〜0.035**）。「形」は Three.js geometry。
> 色は constructivist パレットのみ。**角丸なし・マット（MeshBasicMaterial）**。

## 3. モバイル方針（出すが更に控えめに・具体値）

ユーザー要望でモバイルでも出す。ただし本文が縦積み・全幅になるため、被りを避けて更に絞る:

- **個数**: 各セクション **1〜2 個**に絞る（`drop` 印を間引く）。**ただし「残す 1 個」は実機で確実に視認できる
  solid な塊（赤い実心板・赤い円環など）にする**。実装検証で、薄い黒スラブ（面）・cream 稜線のみ・黒い中空枠は
  小サイズ＋低不透明度の実機でほぼ見えないと判明したため、各セクションは**視認できる赤の塊を必ず 1 つ含める**:
  → モバイルは about=a1+a2（黒板＋**赤点**）/ skills=**s2 の赤円環**（薄い黒スラブ s1 は落とす）/
  ai=ai1+ai2（向き合う楔ペア）/ career=c1（赤い縦柱）/ portfolio=p1+p2（黒枠＋**赤点**）/ contact=ct1（赤円環）。
- **サイズ**: ホスト矩形を **18〜24vmin 四方**（デスクトップ 22〜34vmin より小）。group scale を 0.6 倍程度に。
- **不透明度**: デスクトップ値から **更に 0.7 倍**（例 about 0.30 → 0.21）。**0.18 を下限**とする
  （0.12 では小サイズの塊が実機で視認できず「モバイルにも 3D を」の要望を満たせなかったため引き上げ。contact は 0.18）。
- **配置隅**: 縦積み本文の**読み帯に被らない隅**へ。原則 §2 の隅を維持しつつ、
  本文が全幅になるセクションでは隅を**最外周にさらに寄せ**（`right-2 bottom-2` 等、画面端 8px 程度）、本文段落の縦の流れと重ねない。
- **モーション**: spin を更に 0.7 倍（電力節約）。bob は **無効**（モバイルは bob なし）。
- **判断の最終権**: 実機で読みづらい/重い場合、frontend は**そのセクションのモバイル 3D を静的 SVG または非表示**に落としてよい（性能・可読性優先。§6 のフォールバックを流用）。

|-----------|------|--------------------------|----------------------|------|
| about | 明 | 0.30 | 0.21 | 紹介文の右下余白。black/red は明背景で強いので低め |
| skills | 暗 | 0.34 | 0.24 | red 円環主役。cream 稜線は薄く |
| ai | 明 | 0.34 | 0.24 | 楔ペアがモチーフなので少し見せる。それでも脇役域 |

  3D 矩形は本文カラムの読み幅に重ねないので、テキストの背後コントラストを変えない。

## 5. 性能方針（Hero で three ロード済み前提・現実的指針）

「各セクションに重い独立シーンを作らない」が核。

- **共有が望ましいが必須ではない**: Hero `ProunCanvas` が既に `three` を動的 import 済み（同一バンドルチャンク）。
  各 `SectionAccent` も `import('three')` する（同チャンクなので**追加ダウンロードは発生しない**）。
  推奨アーキテクチャ:
  - **単一の共有 React コンポーネント** `SectionAccent.tsx` を作り、`section` prop（`'about'|'skills'|...`）で §2 の表を切り替える。
    Hero の `ProunCanvas.tsx` を雛形に、オブジェクト数・占有・不透明度を脇役向けに落としたもの。
  - 各セクションは `<SectionAccent client:visible section="about" />` のように 1 行で差す。
- **可視外で rAF 停止**: `IntersectionObserver`（`ProunCanvas` と同実装）。可視セクションの 3D のみ描画。
  **複数セクションが同時に可視になりうる**ので、各 instance が自分の可視判定で独立に start/stop すること。
- **タブ非アクティブで停止**: `visibilitychange` で全停止。
- **DPR 上限**: `min(devicePixelRatio, isMobile ? 1.5 : 2)`（`ProunCanvas` と同値）。
- **ポリゴン少数**: 各セクション合計 **数百三角形以内**（box/torus 低 segment。torus は radial 10〜12, tubular 36〜40）。
  Hero（〜2000）より更に軽い。1〜3 メッシュなので negligible。
- **小さいレンダラ**: ホスト矩形が 18〜34vmin と小さいので描画ピクセルが少ない。複数同時でも軽い。
- **dispose**: アンマウント時に geometry/material/renderer を `dispose()`、canvas 除去（`ProunCanvas` と同様）。
- **同時稼働の上限**: 画面内に可視な SectionAccent は通常 1〜2 個。それ以上は IO で停止。
  万一全部動いても 1〜3 メッシュ×6 = 最大 18 メッシュ程度で軽量。シャドウ・ライトなし（MeshBasicMaterial）。
- **マテリアル**: `MeshBasicMaterial`（フラット・ライト不要）。Hero と同方針。陰影を出さないので darkgray 面は使わない。

## 6. フォールバック（reduced-motion / WebGL 非対応）

- **判定**: `prefers-reduced-motion: reduce`（`matchMedia`）または WebGL 非対応で 3D を起動しない（`ProunCanvas` の `supportsWebGL()` を流用）。
- **静的フォールバック**: 各セクションの主オブジェの**静止 SVG（軸測 1 隅小片）**を同じ隅に表示。
  - インライン SVG をコンポーネント内に持つ（`ProunFallback` と同方式）。`public/decoration-fallback/section-*.svg` でも可。
  - フォールバックでも「about=黒板＋赤小板」「skills=黒板＋赤円環」「ai=向き合う 2 楔」「career=赤い縦棒＋ダイヤ」
    「portfolio=黒い中空枠＋赤点」「contact=赤い円環」の**各モチーフが静止で読める**こと。
  - 色は constructivist パレットのみ。明背景は black/red 実面、暗背景は red＋cream 稜線（黒は stroke で見せる）。
- **モバイル × reduced-motion**: §3 のモバイル絞り（1 個）の静止 SVG を出す。重ければ非表示でも可。

## デザイン指針（まとめ）

- **脇役に徹する**: Hero showpiece と格を分ける。1〜3 個・1 隅・低不透明度・更に緩慢。占有を全面に広げない。
- **語彙は増やさない**: Proun 語彙（box/楔/円環/棒/中空枠）の小片を、配色・配置・密度で各セクションに変奏。
- **明暗でエッジ・配色を切替**: 暗背景=cream 稜線で黒を見せ red 主役／明背景=black/red 実面で cream 面は使わない。
- **本文を絶対に邪魔しない**: 読み幅・H2 の背後を避け、外周の隅へ。半透明・下層で AA を下げない。
- **2D タイルと喧嘩しない**: 2D が疎な隅に小さく重ね、面で競合させない。隣接セクションで同じ隅に連続させない。
- **モバイルも出すが更に控えめ**: 1 個・小サイズ・低不透明度・bob なし。読みづらければ frontend が静的/非表示に落とす。
- パレット外の色を導入しない（新色が要るなら本 spec に理由とトークン追加案を先に書く）。
