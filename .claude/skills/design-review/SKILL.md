# デザインレビュー手順

対象（セクション/コンポーネント）を1つ決めて、以下を順に確認し、各項目 OK/NG と理由を記録する。

## 1. デザイン言語の忠実度
- [ ] 色は `tailwind.config.mjs` の `constructivist.*` トークンのみ（パレット外の色がない）
- [ ] シャープエッジ（角丸なし）・ボールドタイポ・大文字・幾何学装飾が保たれている
- [ ] 語彙を増やすのではなく、密度・配色・構図で変奏している
- [ ] 動的アシンメトリ／対角バランス／余白の拮抗が効いている

## 2. 視覚アクセシビリティ
- [ ] 本文テキストのコントラストが WCAG AA（通常 4.5:1、大文字 18.66px+/太字 24px+ は 3:1）
- [ ] 暗背景（black）・明背景（cream）双方でトークンの組合せが破綻しない
- [ ] 装飾は `aria-hidden` で、情報をテキストでも提供している（色のみに依存しない）

## 3. レスポンシブ
- [ ] モバイルファースト。`sm:`/`md:`/`lg:` で段階的に構図が成立する
- [ ] 狭幅で要素の重なり・はみ出し・可読性低下がない

## 4. モーション
- [ ] アニメーションは `prefers-reduced-motion: reduce` で無効化/静的化される
- [ ] 重い描画（Phaser 等）は遅延ロードされ、装飾がスクロールを奪わない

## 5. 実物確認（任意）
```sh
npm run build && npm run preview
```
必要なら Playwright でスクリーンショットを撮り、暗/明・モバイル幅・reduced-motion を目視する。

## 出力
NG 項目があれば「何を・なぜ・どう直すか」を列挙する。問題なければ受入条件に反映してよい。
