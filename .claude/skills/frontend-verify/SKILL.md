# フロントエンド検証手順

## 1. 型・診断チェック
```sh
npx astro check
```
- 0 errors を必須とする。エラーがあれば原因箇所を直してから次へ。

## 2. 本番ビルド
```sh
npm run build
```
- 失敗を残さない。
- 重い依存（Phaser 等）が**別チャンクに分離**され初期バンドルに載っていないことを、
  ビルド出力のチャンク一覧で確認する（遅延ロードの回帰防止）。

## 3. 実物確認（変更が視覚/挙動に及ぶ場合）
```sh
npm run preview   # http://localhost:4321/nigoh/
```
- 必要なら Playwright（環境に応じて `/opt/pw-browsers/chromium` を指定）でスクリーンショット。
- 確認観点: 主要セクションの描画、レイアウトシフト無し、`prefers-reduced-motion` で
  静的フォールバック、モバイル幅でスクロールが奪われない。

## 4. 受入条件の検証
- 対象の `specs/**/*.spec.md` の受入条件（`- [ ]`）を1つずつ確認し、満たしたものを `- [x]` に更新する。
- 満たせない項目は理由を添えて残す。

## 5. 報告
「変更点 / `astro check`・build の結果 / 実物確認 / 受入条件の充足 / 残課題」を簡潔にまとめる。

> 注: frontend エージェント終了時には SubagentStop フックが `astro check` を自動実行する
> （src 変更時のみ）。失敗すると終了が差し戻されるため、ここで先に通しておくこと。
